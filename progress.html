Phase 7: Add guardrails

Milestone 3

  • list_equipment no longer sends item notes to any model, and every tool result is screened: a name or note that reads like an instruction is replaced (backend/src/domain/guardrails.ts, applied in the shared tools.ts, so the MCP server and both chat backends get it).
  • Output guardrails for both chat backends (backend/src/agent/turn.ts): a reply that claims a loan is saved, or offers more than 2 items or 7 days, is replaced by a fixed one built from the tool results. The reply lists which guardrail fired.
  • check_stock now returns the closest valid suggestion on a refusal (4 kits for 14 days gives 2 kits for 7 days), so the offer comes from code, not from the model's arithmetic.
  • The API flags the injected note (notesFlagged) and the UI shows it as ignored.
  • Tests: case 5 is blocked through the MCP server, the API, the OpenAI-compatible agent and the Claude SDK agent, including scripted models that obey the note or claim a save. 114 backend tests pass.

Phase 6: Write evals for the prompts

Milestone 3

  • The five cases as nine conversations (backend/src/evals/cases.ts). Each runs on a temp copy of data.json and fails if the reply is wrong, if it does not name the rule code, or if the data changed.
  • Two prompts (backend/src/agent/prompt.ts): v1 is the Milestone 2 prompt; v2 asks one question for everything missing, starts refusals with the codes word for word, offers the suggestion from check_stock, and keeps replies short. v2 is now the default; AGENT_PROMPT switches.
  • Run with npm run eval -- --provider claude-sdk against real Claude (Claude Code login). Results in evals/results/latest.md:

  • Both prompts are correct on every case with Claude; v2 gives the same outcomes with replies about 40% shorter and about 20% faster. A test with a scripted model shows the evals catch a model that guesses instead of asking (case 4).
  • Not done: the same comparison on a free OpenAI-compatible model (Ollama, Groq, Gemini); run npm run eval with one in .env.

Phase 5: Add the agent to the UI

Milestone 2 · branch group-4/milestone-2

  • Added a chat panel to the UI (frontend/src/Chat.tsx) and POST /api/chat.
  • The agent (backend/src/agent/) has two backends chosen in .env: the Claude Agent SDK (LLM_PROVIDER=claude-sdk, no built-in tools) or any OpenAI-compatible API. Both use the same tool list as the MCP server. Added the @anthropic-ai/claude-agent-sdk and zod dependencies, at the user's request.
  • The model gets only list_equipment and check_stock. It never gets create_loan: the Approve button is the only way to save, and the student id comes from the session.
  • A proposal is returned only from a successful check_stock, not from the model's words.
  • Tests with a scripted model for cases 1, 3, 4 and 5, and endpoint tests for the 400 and 503 cases.
  • Not done: a run against a real model (needs a key in .env), evals and prompt comparison (Milestone 3).
